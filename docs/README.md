## 維護原則

- 現行行為由程式、出貨的技能程序與測試共同核對；文件不另立一套規格。
- 同一主題維持一份摘要，以連結指向實際來源，不再複製完整程序、舊行號、簽核與施工進度。
- 已完成的日期式設計、修錯診斷、重複研究及暫存問題清單已移除。需要追溯已納入版本控制的原文時，使用版本控制工具（Git）的歷史紀錄；未納入版本控制的舊筆記不視為專案契約。
- 第二版架構保留獨有的需求與決策，但明確隔離為未實作提案。它沒有取代現行四階段及資料格式。
- 歷史評估只保留有用的數字與限制，不將當時價格、模型或測試數當成今日保證。
- 本專案刻意忽略 `docs/`；新增的重要文件須由維護者明確納入版本控制，規則見 [CLAUDE.md](../CLAUDE.md)。
